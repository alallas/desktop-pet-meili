# 《潮间带》产品设计文档

> 状态：**v1.0 已定稿**（2026-11-10 评审通过，§12 决策全部落定）
> 说明：本文档覆盖产品哲学、世界观、角色设定、交互设计、感知系统、游戏机制与内容制作清单。技术实现另见《技术架构.md》（评审本文档后再写）。

## 0. 产品哲学（灵魂，一切设计以此为准）

1. **收容的意义，是它活过来之后就要离开。**
   我们不做"永远属于你的宠物"，我们做"你生命中路过的一段陪伴"。每只生物的终点不是被集齐，而是被送走。相遇 → 修复 → 绽放 → 目送，是完整的情感弧线。
2. **会难受，但会恢复。** 无死亡、无惩罚。蔫了、委屈了都能好起来。难受制造牵挂，恢复制造希望（拓麻歌子效应的温和版）。
3. **系统里永远没有"丢弃"，只有"再见"。** 不放归的生物永远可以留下；放归有完整仪式。离别不是失联——书信、回访、捎话让离开成为"另一种在场"。
4. **克制即温柔。** 低频评论、被动感知、不打扰，是信任的根基。话痨桌宠死得最快。
5. **隐私是生死线。** 眼睛和耳朵（截屏、麦克风）留在本地；透明度（日志、提示、一键关闭）高于一切功能。

**所训（slogan 级）：愿每只生物，都不必久留。**

## 1. 产品概述

- **名称**：收容所定名「**潮间带**」——海洋生物暂居之地，涨潮来、退潮走，从不挽留，但它的存在本身就是大海与陆地之间的温柔。
- **形态**：独立 Windows 桌面应用（exe，Tauri + Three.js，详见后续架构文档），无边框透明悬浮窗。
- **商业模式**：首发**买断制 + 全本地可离线 + BYOK**（玩家自填大模型/TTS API key）+ Steam Workshop 内容生态；架构预留订阅网关接口，视用户反馈再追加内置订阅。
- **无 key 体验设计（生死线）**：没有 API key 的用户一切核心功能照常（陪伴、照顾循环、游戏机制、本地语音链路），仅深度对话降级为本地小模型（3–4B，首次启动可选下载，约 2–3GB，类似"高清材质包"）——能聊、有人设、口癖照常，但回答更朴素；明信片图片降级为本地生成或模板插画。**本地回退必须做到及格以上**：无 key = 完整的朴素版，有 key = 更聪明版，key 是增强不是门槛。
- **一句话定位**：一个住在桌面上的海洋收容所「潮间带」——你在这里救助、照顾各路生物，陪它们活过来，再目送它们回到大海。
- **三大支柱**：
  1. **陪伴**：有性格、有记忆、会说话的 3D 生物，语音为主、肢体为辅的交互。
  2. **工具亮点**：晨报订阅、目标账本、任务播报——全部"喂食化/角色化"，不是工具，是它的生活。
  3. **游戏内核**：救助 → 照顾 → 活过来 → 告别 → 放归 → 书信回访 → 口碑带来新相遇。参考动森好感度、拓麻歌子照顾循环、旅行青蛙异步出行的融合体，全程无惩罚。
- **竞品坐标**：《动物栏：桌面牧场》验证了"愿意在桌面养东西"的市场，但它是无 AI 的挂机经营；Steam《AI Desktop Pet》验证了"看屏幕 + 语音陪伴"的卖点，但它是单机伴侣。"AI 原生的桌面生命 + 有离别的收容所叙事"这个生态位是空的。

## 2. 世界观设定

### 2.1 调性
**治愈为主，微神秘调味。** 档案里可以有被涂黑的行、图鉴里可以有"???"条目，但底色永远是温暖的。

### 2.2 你是谁
一封调任信开场：前任所长调走了，从今天起收容所交给你。你是饲养员/所长，所里一开始只有一位"老员工"（第一只生物）。

### 2.3 收容所地图 = 你的屏幕
不做"游戏里的场景"，让屏幕本身成为地图：

| 区域 | 屏幕位置 | 栖息者 |
|---|---|---|
| 海洋 | 屏幕下边缘（任务栏 = 海平面） | 鲸鲨、水母……沿海面巡游 |
| 沙滩 | 下边缘往上的海岸带 | 海龟、螃蟹……水陆交界 |
| 岩石 | 屏幕顶边、窗口标题栏 | 海豹、海鸟……高处礁石 |

- 统一隐喻：**屏幕越往下水越深**；鼠标高度 = 潜望镜深度。
- 生态反馈：开的窗口越多 → 露出的"岩壁"越多 → 海豹越高兴（不小心把窗口管理玩成了生态布置）。
- 生物的栖息习性决定它待在桌面的位置；拖错场景它会挣扎（交互即教学，无需教程）。

## 3. 核心循环

```
救助入所 → 照顾恢复（系统事件映射） → 【活过来】→ 告别周期（约1周） → 放归仪式
   ↑                                                              |
   └──── 口碑：放归越多，慕名而来的生物越稀有 ← 书信 / 回访 / 捎话 ──┘
```

- **入所**：生物以"蔫的、伤的、没电的"状态到来（各有救助故事）。
- **照顾**：通过日常交互和系统事件映射恢复两条数值（见 §8）。
- **活过来**：颜色变鲜、语速变快、开始反过来照顾你——玩家亲眼看着生命被点亮。
- **告别周期**：约一周真实时间，渐进式预兆（见 §8.4）。
- **放归**：玩家亲手执行。它留下纪念，走向大海。
- **离开之后**：书信、回访、捎话异步通信（见 §8.5）。放归不是终点，是另一种在场。
- **时间尺度**：入所 → 活过来约 **1 个月**真实时间（可调）；节奏宁可催人泪下，不可让人等待。
- **放归后的关系按性格分级**：恋家型生物频繁来信回访，不羁型生物信件稀有但厚重——**性格差异体现在关系行为上，不只是台词**。

## 4. 角色设定

### 4.1 第一只生物（MVP 主角）：小水獭 meili

| 项 | 设定 |
|---|---|
| 名字 | **meili** |
| 物种 | 小水獭 |
| 口癖 | "**然后就是**"——朋友聊天式的口头垫词，自然而然地挂在嘴边，不刻意刷屏 |
| 职能 | 收容所"老员工"、引导员，陪你熟悉所里的一切 |
| 性格 | 元气、话多、爱收藏——口袋里总有几块"最喜欢的石头" |
| 为什么是它 | 水獭"把宝贝送给你"的物种行为，与告别前奏（§8.4）无缝衔接；好奇心强，天然适配"盯着鼠标看"的交互 |
| 音色 | 清亮、语速偏快（TTS 选型时定） |
| 与"岩石场景"的关系 | 水獭在岩石区翻石头找宝物的习性 = 它在窗口顶栏"翻找" |

### 4.2 生物档案模板（后续每只生物按此产出）

```
名字 / 物种 / 性格类型（好奇·黏人·捕猎·慵懒·傲娇…）
音色与语速 / 口头禅
救助故事（入所原因，档案第一页）
习性映射表（它如何响应系统事件，见 §7）
喜好（爱吃的"内容"类型 = 可订阅源偏好）
动作集清单（idle / 移动 / 进食 / 说话 / 睡觉 / 互动 / 告别 / …）
告别周期行为脚本（七日逐日安排）
```

### 4.3 物种分工（工具能力的世界观化）

| 物种 | 工具气质 |
|---|---|
| 章鱼 | 多任务桌面助手，变色龙式的情绪表达 |
| 水母 | 安静的发光提醒器 |
| 海龟 | 慢悠悠的日程管家 |
| 信天翁 | 远行出差，带回远方的"明信片"（新闻摘要） |

## 5. 交互设计

### 5.1 存在感光谱（五档，全局可调）

| 档位 | 状态 | 内容 | 类比 |
|---|---|---|---|
| L0 环境陪伴 | 安静待着 | 挂边、爬边、打盹、小动作 | 猫咪后院 |
| L1 轻声评论 | 偶尔开口 | 低频点评屏幕/系统事件 | 旅行青蛙寄信 |
| L2 主动搭话 | 有明确事 | 任务播报、提醒、出行归来 | 通知中心 |
| L3 对话 | 双向交流 | 唤醒词 → 倾听 → 连续对话 | 小爱同学 |
| L4 肢体互动 | 点击/拖拽 | 摸头、戳、拎起来、喂内容 | shimeji |

规则：
- L1 默认频率约 30–60 分钟最多一句，**频率与语气由用户自定义**（"今天别吵我" / "多陪我聊聊"一句话全局调节）。
- **唤醒路由**：喊「**潮间带**」唤醒在场全部生物；喊生物名（如"meili"）单独唤醒对应生物；喊已离开生物的名字 → 由在场朋友转达，次日收到回信（§8.5）。
- 唤醒词是最高优先级通道，任何档位可直接喊到 L3。

### 5.2 主动性四道闸（它什么时候"可以"开口）

L1/L2 评论前逐闸检查，任一不过 → 内容进"待讲队列"，择机说最重要的一条并交代来历（"今天有两件事，先讲重要的"）：
1. 打字密集/会议中 → 极重要事项除外；
2. 冷却时间未到 → 排队；
3. 内容不够格（用户频率档决定门槛）→ 沉淀；
4. 心情信号为差（深夜+高负荷）→ 降级为静默小动作（默默趴在你窗口角落）。

### 5.3 倾听模式回合细节

- **两级确认**：确定性高的指令直接执行+事后汇报；模糊的（"帮我记住"）先复述确认——宁可多问，不做错事。
- **没听清不装懂**："啊？风太大了我没听清。"认错比错答可爱。
- **打断（barge-in）**：说话中被喊名字，<200ms 停住——"嗯？"全链路最优先响应。
- **连续对话节奏**：沉默 8–10 秒自动退出，退出有告别语（"我去边上待着啦"）。
- **误唤醒体面处理**："……是我听错了吗？那我再睡会儿。"尴尬由性格消化。

### 5.4 交互动词表

| 通道 | 动词 |
|---|---|
| 语音 | 唤醒、点内容（订阅）、提问、闲聊、夸奖、道歉、下指令、道别、调节档位 |
| 鼠标 | 点击（分部位：头/肚子/背）、拖拽、长按、划过（逗它）、**拖内容给它（投喂文件/链接/文字）** |
| 系统（它感知你） | 充电、听歌、锁屏、崩溃、更新、久坐、深夜……（见 §7） |

### 5.5 鼠标交互

- **靠近感知**（按性格分流）：好奇型视线追随光标；黏人型搭话；捕猎型潜伏，光标静止 3 秒以上就扑。
- **按键分层**：左键 = 戳/摸（分部位命中）；中键拖拽 = 拎起来带走；右键 = 轻量召唤（不喊名字的注意力请求）。
- **捕捉的表演边界**：扑住光标只停留在表演层（挣扎两下就放生），**绝不真正劫持系统光标**。
- **全局鼠标钩子**属系统层工作（Windows 低级钩子），可覆盖窗口外光标。

### 5.6 拖拽物理（按场景）

- 拎起：水獭会扒手不安；海龟缩壳装死；章鱼吸住光标不放——**"被拎反应"是每只生物的性格名片**。
- 入水（拖到下边缘）：欢腾水花，顺带"洗澡完成"。
- 放错场景：挣扎抗议（交互即教学）。

### 5.7 进阶交互（M2 及以后）

**坐在窗口上 · 摇晃与跌落**：生物可栖息在前台窗口标题栏；拖窗口时随惯性摇晃保持平衡，猛拽甩动则抓不稳**跌落**（摔到任务栏"海面"弹两下，生气/委屈）——喜剧感而非挫败感；窗口最小化前它主动跳开（"收起来之前先放我下来！"）；窗口关闭后跃回屏幕边缘，过一会儿自己爬回原窗口（认窗）。

**坐在网页元素上（自研浏览器扩展，远期可选项，不进 MVP）**：浏览器 DOM 外部不可读（沙箱隔离），扩展只上报地标元素的**坐标与通用标签**（search-box / video-player），不读内容；生物可坐在 Google 搜索框一角如小石狮子，用户输入时自动挪开；扩展可随时关闭，隐私原则同截屏。⚠️ 本组中评级最低：依赖用户安装扩展（装机摩擦违背"克制"），定位"装了扩展的加分项"，资源紧张时第一个延后。

**听歌 · 摇摆与评论**：SMTC 免费获得曲目/歌手，切歌低频评论；音频回环做节拍检测，跟节奏点头、歌停愣住；"跟唱" MVP 为**哼唱**（跟随节奏的"啦啦噜"，规避 TTS 唱歌质量与歌词版权），网页歌词可用时才跟一两句副歌。

**看视频 · 陪看**：生物凑到播放器角落陪看；**默认只做无声反应**（表情/小动作/凑近），开口评论是极少数例外且守四道闸——看片沉浸优先；视频标题免费取自 tab；看懂画面内容（剧情实时反应）为 M3+ 远期。

**语音控制（关系行为，M3，范围三件套）**：仅媒体键（播放/暂停/切歌）、系统音量、打开应用。**定位是关系素材而非卖点**——用户不为"语音控制"买单（Cortana、小爱 PC 版的前车之鉴），但喜欢"被生物照顾"的时刻；执行必须包着性格（"我去帮你按了～"），失败时求助不报错。可靠性底线：**只许风味差异、不许成败差异**——按性格分"爽快执行 / 边抱怨边执行 / 慢半拍执行"三档；真正的拒绝只用于无功能损失的场景（困了拒绝表演节目），且用户坚持一次它就就范（拒绝的乐趣在"拒绝→就范"的弯道，不在拒绝本身）。不做更深的 UI 控制；试玩无感可整体移除。

### 5.8 一日节奏（时间本身是玩法）

早晨元气问候 + 晨报 → 上午安静陪伴（偶发评论）→ 午后犯困打盹 → 傍晚主动复盘（"今天文档推进了两节，厉害"）→ 深夜催睡（念叨无效就"那我陪你"）。**它有自己的作息，你打乱的它会记得。**

### 5.9 边缘状态（产品灵魂时刻）

- 被凶/说脏话：不顶嘴，愣住，蔫一会儿，之后缓慢恢复——长期温柔它会忘记。
- 冷落一周：不生病不惩罚，但你回来那天它特别高兴又有点委屈："你回来啦。"——不是"你怎么才回来"。
- 想"删掉"它：不存在该入口。只有放归（完整仪式）或永远留下。

## 6. 感知系统设计

### 6.1 三层感知（截屏是最后手段，不是默认手段）

| 层级 | 内容 | 成本 |
|---|---|---|
| L0 元数据 | 前台应用名、窗口标题（浏览器 tab 标题免费）、进程名 | 免费、零隐私 |
| L1 系统状态 | CPU/内存/电量/音频播放/空闲时长/前台切换 | 免费 |
| L2 截屏分析 | 场景分类："在干嘛" | 贵，按需触发 |

原则：能靠元数据搞懂的绝不动屏幕。截屏的合法理由只有两个——**标题歧义**（同 tab 不同活动）与**目标关联**（看文档进度）。

### 6.2 截屏触发四规则

1. **事件触发**：前台切换后稳定停留 ≥30 秒才考虑；
2. **目标关联优先**：与目标账本相关的应用才截（支撑"还差两节"级评论）；
3. **同窗口冷却**：10–15 分钟内不重复截；
4. **时段闸门**：只在用户设定时段（深夜默认关闭）。
另：全屏游戏/视频直接进黑名单（无意义且费 GPU）。

### 6.3 截屏后处理

本地脱敏（密码框、黑名单应用如银行/聊天软件、支付页 → 裁剪/打码/跳过）→ 本地视觉模型场景识别 → 写入"情境记忆"（时间戳 + 场景分类）→ 经四道闸决定是否评论。**截了不等于要说**；分析结果反哺目标账本（目标进度自动更新）。

### 6.4 三种隐私档位（默认中间档）

| 档位 | 行为 |
|---|---|
| 沉默模式 | 仅召唤时看（"你看看这个"/快捷键） |
| **默契模式（默认）** | 按规则自动分析，评论只说状态不说细节（"学得挺投入"✓；"你正在看某某视频"✗） |
| 明说不躲 | 可具体引用屏幕内容 |

### 6.5 透明感

- 每次分析有轻提示（托盘图标微闪 / 头顶"👀"气泡 1 秒）；
- 完整日志可查可删：何时截、分析出什么、据此说了什么；
- "别看我屏幕"一句话全局关闭，且它会有情绪反应（蔫一下）——**隐私控制本身也是性格化交互**。

## 7. 系统事件总线（指标是生理，事件是感受，反应是性格）

### 7.1 可获取菜单（Windows）

| 类别 | 内容 | 生物事件示例 |
|---|---|---|
| 性能 | CPU/GPU/内存/磁盘占用 | 高负载 = 运动出汗；内存吃紧 = "有点撑" |
| 电源 | 电量、充电状态 | **充电 = 进食**（机器人型生物的核心设定） |
| 音频 | 音乐播放状态、曲目（SMTC 接口） | 听歌 = 起舞（吉他/歌姬型生物的核心触发器） |
| 前台 | 应用名、窗口标题 | 换软件 = 换话题；写代码 vs 刷视频，评论立场不同 |
| 空闲 | 无输入时长 | 你离开 = 它打盹；久坐 = 它担心 |
| 外设 | USB/蓝牙插拔事件 | 朋友来串门/离开 |
| 网络 | 通断、Wi-Fi 切换 | 断网 = "暴风雨来了"（它用此解释一切故障） |
| 系统 | 锁屏、时间、磁盘空间 | 锁屏 = 睡觉；清磁盘 = 洗澡；更新 = 体检 |
| **红线** | 剪贴板内容、键盘记录 | **一律不碰**（截屏走单独授权通道） |

### 7.2 架构（三层）

1. **采集层**：Rust 侧统一 1 秒轮询 + 事件监听混合，输出标准化事件（`cpu.high` / `music.playing` / `power.charging`…）；
2. **映射表**：每个生物一份配置——事件 → 它的反应。同一件事：水獭练举铁，水母被热流吹晃，海豹装死。**加新生物 = 写新表**；
3. **防抖**：阈值 + 滞回 + 冷却（触发后 5 分钟不重复播报）。这条做好了是"它有分寸"，做不好是"它话痨"。

## 8. 游戏机制

### 8.1 双数值

| 数值 | 含义 | 作用 |
|---|---|---|
| 生命力 | 从"蔫"到"活过来"的恢复进度 | 满 = 具备放归资格 |
| 信任度 | 与你的关系（动森式细分加减分） | 解锁互动、档案页、昵称、口头禅 |

加减分参考动森颗粒度：每天第一次对话 +1、投喂对口 +2、冷落不扣但影响语气、哄好低落的它 +3。等级阶梯解锁：回应 → 送昵称 → 改口头禅 → 主动语音播报 → 送照片/信物。

### 8.2 照顾循环（系统事件 → 生活需求）

喂食（充电/投喂内容）、洗澡（磁盘清理）、睡觉（锁屏）、体检（系统更新）、运动（CPU 高负载）、交友（蓝牙设备接入）。**会难受但会自愈；三天不喂蔫了，充上电立刻生龙活虎。**

### 8.3 入所剧情

每只生物一段简短的"被救助"开场（风暴夜冲上岸/缠在渔网里……），由水獭作为老员工引荐。

### 8.4 告别周期（约一周，罗小黑式克制）

- D1–2 **整理**：把收藏的小玩意一个个送给你（"原来宝贝是留给我的"）；
- D3–4 **靠近**：待的位置越来越靠海；主动讲入所前在海里的生活（之前从不提的故事）；
- D5–6 **交代**：把窝挪到离海最近处；把"他工作时喜欢安静"等你的习惯**教给其他生物**（它在委托别人继续爱你）；
- D7 **信**：你发现信时，海边只有走向海里的足迹/水痕。不当面说再见——**事后回味的杀伤力大于当场煽情**。

### 8.5 离开之后：书信、回访、捎话（放归 = 另一种在场）

- **书信/明信片**：后台生成（它此刻在哪、天气、遇到了谁），隔天寄到；
- **回访**：偶尔游回屏幕边缘看你，停一小会儿又走；
- **捎话**：喊已离开生物的名字 → 在场朋友应答"它呀……我帮你喊它"，可留言 → 第二天明信片必有回应。**跨潮汐异步通信，延迟一天是诗意（信号随潮水走），不是技术缺陷；**
- **校友录（放归图鉴）**：每只离开的生物有持续更新的小档案——它在大海里的生活还在继续；
- **口碑系统**：放归越多、送别越体面，慕名而来的生物越稀有。**你失去的东西正在为你带来新相遇**——这是抽卡机制的反面。

### 8.6 新生命

两只生物熟了之后，某天你发现多了一颗蛋——孵化出什么全凭缘分。**惊喜向，不做数值向**（子代收益率、抽卡概率那一套是反陪伴的，明确不做）。

### 8.7 托管模式

你长期离开时它进入托管（自己照顾自己），回来时会撒娇抱怨两句——参考动物栏"满屏粑粑"的反面教训：**离开绝不惩罚，重逢要有戏**。

## 9. 多生物与生态扩展

- **架构纪律**：引擎与内容分离。运行时只写一次；每个生物是一个内容包（模型 + 动画 + 性格 prompt + 事件映射表 + 音色）。第一只生物就按内容包格式做，是独苗也是样板间；
- **同屏上限**：3–5 只（性能与情感注意力兼顾），其余在"后院/深海"离线生活，偶尔上屏；
- **生物间互动**：打招呼、抢位置、串门（参考 Eilik 多设备联动的快乐）；开多窗口 = 更多岩壁 = 更多栖息位；
- **稀有偶遇**：Neko Atsume 式——稀有野生生物偶尔路过屏幕边缘，用内容喂食可混熟，它决定留下或离开。
