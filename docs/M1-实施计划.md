## 2. M1-1 工程地基（3–5 天）—— ✅ 完成（2026-11-12）

**内容**：仓库结构按架构 §8 + 工程规范 §1 成型；IPC 协议定版；SQLite schema 落地；构建/签名/打包流水线；**工程规范 §6 的 CI 六项检查全部跑通**（fmt/clippy/test、eslint/tsc/vitest、IPC 生成物校验、license 扫描、安装包冒烟）。

- 目录结构：`src/{behavior,presentation,game,pets-runtime,ui}`、`src-tauri/src/{event_collector,perception,voice,cloud,db,steam,hooks}`、`pets/meili/`
- **IPC 协议定版**（先定协议再写模块，避免返工）：
  - Rust→WebView：`event`（标准化事件 JSON）、`speech`（TTS 音频流/文本）、`state`（生物状态同步）
  - WebView→Rust：`invoke`（指令：移动窗口/播放音频/读写设置/云通道请求）
  - 事件 JSON 骨架：`{id, ts, source, kind, payload, privacy_tier}`
- **SQLite schema**（架构 §3.8 八张表）+ 迁移机制（rusqlite + 版本表）；**写穿策略**：信任度等关键事件立即落库，高频流水 5s 批量
- 决策项消化：**#2 窗口形态定案**（覆盖层 vs 小窗）、**#1 移动双通路**细化进窗口管理器设计
- 打包流水线：tauri build + WebView2 引导 + 第三方许可声明页生成（§9.1 义务）

**交付**：空壳应用能装能跑；八张表建好；IPC 两端打通一个 ping-pong 样例。

## 3. M1-2 系统层事件采集（4–6 天）—— ✅ 完成（2026-11-12，M1-2.1–2.4 四个提交）

**内容**：架构 §3.1 全部事件源，事件驱动为主。

- 前台窗口（GetForegroundWindow + 进程名）、SMTC 音乐、电源、空闲时长、全局鼠标（WH_MOUSE_LL）、自窗口位置、前台窗口位置变化（SetWinEventHook，M0-9 已验证）、网络、锁屏
- 统一**防抖器**（阈值+滞回+冷却 5min 默认）后上事件总线
- 性能红线：静默常驻 CPU <1%（事件驱动 + ≤1Hz 校验轮询）
- 决策项消化：鼠标事件的范围与频率上限（防杀软误报，§9 风险表）

**交付**：事件监视器调试页（WebView 实时看事件流——这个页面将贯穿 M1 所有阶段）。

## 4. M1-3 语音管线（6–8 天，风险最高）

**内容**：架构 §3.3 产品化。

- **常驻唤醒**：sherpa-onnx KWS（词表"美丽/美丽你好"，M0 全套参数迁移）Rust 常驻，内存 <100MB
- **倾听**：VAD 断句 → SenseVoice 流式转写 → 意图路由（本地规则 / 本地 LLM / 云端 BYOK）
- **TTS**：Kokoro sidecar（M1 先用 Python sidecar 过渡，M2 评估换 sherpa-onnx TTS 或 ONNX 原生绑定）；**待办 #10 流式化**（首音 <1s）、**#12 唤醒截断回填**（环形缓冲）
- **打断**：播放中命中唤醒词 <200ms 停止（**#11**，回声消除评估：TTS 播放流与麦克风流的相关性检测做初版）
- **按名路由**：喊"美丽"→ meili；喊"潮间带"→ 全体（M1 只有一只，留接口）
- 验收：无网无 key 时语音对话完整可用（原则 #1）

**交付**：喊"美丽"能聊上，ASR 文本进意图路由，TTS 出声，打断可用。

## 5. M1-4 思考层（3–5 天）

**内容**：llama.cpp sidecar 常驻管理 + 人设系统 + 云通道。

- sidecar 进程管理：按需启动/休眠（性能预算：模型不常驻内存——唤醒或事件触发加载，闲置 N 分钟卸载；M0 实测加载仅 5s 可接受）
- **人设一致性引擎**：system prompt 模板（物种/性格/口癖"然后呢"/当前情绪/信任度分级）+ 每请求注入；本地云端同规则
- Qwen3-4B 固定 `enable_thinking=false`（坑 23）；**#13** 1.7B 对比实验（嘴贫评论场景）
- **云通道**：OpenAI 兼容抽象层 + key 存 Credential Manager + 无 key 自动降级（**#3**）
- **评论生成器**：屏幕事件 → 一句嘴贫（模板优先，LLM 兜底；四道闸在 M1-5）

**交付**：本地生成一句符合人设的评论 <3s（从事件到 TTS 文本）。

## 6. M1-5 行为引擎（4–6 天）

**内容**：架构 §3.4。

- 存在感光谱 L0–L4 + 全局调节指令
- 主动性**四道闸**：待讲队列、冷却、心情信号（时段+负载+空闲）、隐私档参数
- **map.toml 加载器**：事件 → 反应（动画/台词/数值）执行
- 一日节奏编排（作息表）
- 决策项消化：**#4 截图理解路线**对接口预留（感知管道 M1 先做触发器+元数据级，VLM 评论走待办 #4 结论）

**交付**：一套可热更的事件映射表驱动 meili 对系统事件做出反应。

## 7. M1-6 表现层（5–7 天）

**内容**：架构 §3.5。

- 动画状态机扩展：idle/移动/说话（口型）/睡觉/悬挂/被拎/告别（M0-2 基础上加状态与 blend）
- 视线 IK 保留（M0 已验证）；**巡逻走 JS 内移动**（双通路 #1 的结论）
- 气泡/信件 UI（DOM 覆盖层）
- 拖拽跟随 + 松手物理（与 M1-2 的 SetWinEventHook 无关——是自己窗口被拎）；**坐到别的窗口上**的摇晃/跌落（M1 先做"前台窗口标题栏吸附"原型）

**交付**：meili 会走、会看光标、会说话带口型、被拎会晃。

## 8. M1-7 游戏循环（5–7 天）

**内容**：架构 §3.6 的 M1 子集。

- 双数值曲线（信任度/生命力）+ 照顾循环（喂食/清洁/互动动作的最小集）
- 七日告别调度器：**开发模式支持时间压缩**（1 分钟=1 小时之类），否则没法测
- 书信生成器（模板 + 本地 LLM）与投递队列
- 图鉴/档案最小 UI

**交付**：能从收容到告别走完整一遍（压缩时间模式），信件送达。

## 9. M1-8 meili 内容包（3–4 天，可与 5–7 并行）

**内容**：pets/meili/ 按 petpack v1 产出完整内容。

- pet.toml（好奇性格、恋家型回访、双曲线引用）
- map.toml 首轮事件映射（≥20 条：充电/听歌/看视频/熬夜/ idle /前台切换…）
- voice.toml（zf_xiaoxiao、语速、口癖频率）
- dialogue/ 台词库（场景×事件×好感度三级，先 60–100 条）
- archive/ 收容档案 + 信件模板 + 告别脚本

**交付**：改内容包不改代码能改变 meili 的行为与台词。

## 10. M1-9 集成验收（3–5 天）

- **性能预算核对**（架构 §7 全表逐项实测）
- **隐私三档**实机切换验证；"别看我屏幕"指令全局生效
- **无网 + 无 key** 全流程演练（原则 #1 的终极验收）

## 11. 风险与对策（M1 新增）

| 风险 | 对策 |
|---|---|
| sidecar 进程生命周期管理复杂（崩溃/僵尸） | 守护线程 + 健康检查 + 自动重启；崩溃时降级为"沉默模式"不闪退 |
| 语音链路多组件串联，延迟叠加超预期 | 各环节 M0 有基线；集成后分段打点，超标环节单独优化（TTS 流式优先） |
| 人设一致性靠 prompt 工程，效果不稳 | 台词模板优先 + LLM 兜底的双轨；口癖后处理兜底（生成后校验"然后呢"频率） |
| 窗口形态决策返工波及面大 | ✅ 已规避（2026-11-12 定案：小窗为主+特效层，见架构 §3.5） |
| 时间压缩测试引入的 bug 混进真实流程 | 压缩时钟走独立时间源，发布版编译期剔除 |
