## 0. 速查：标准开工姿势

```bash
source scripts/dev-shell.sh   # 配好 cargo + windres 所需 PATH（Git Bash）
cd src-tauri && cargo build   # 编译
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check-window.ps1  # 验证窗口
```

Git Bash 里直接执行本工程编译出的 exe 会报 `Exec format error`（坑 8），启动一律用：
```bash
powershell -NoProfile -Command "Start-Process 'D:\Repos\desktop-pet-meili\src-tauri\target\debug\chaojiandai.exe'"
```

截屏一律用 DXGI（GDI 会漏拍本工程的透明窗口，坑 8b）：
```bash
python scripts/screenshot_dxgi.py out.png --cursor 2200 1200   # 坐标为物理像素
```

## 1. Rust 工具链与链接

### 坑 1：每个新 shell 里 cargo 不在 PATH
- 现象：`cargo: command not found`（cargo 装在 `$HOME/.cargo/bin`，Git Bash 不自动加载）。
- 解法：`source scripts/dev-shell.sh`，或手动 `export PATH="$HOME/.cargo/bin:$PATH"`。

### 坑 2：MSVC 走不通（本机无 Windows SDK）
- 现象：MSVC 工具链存在，但全盘找不到 `kernel32.lib`（没装 Windows SDK），链接必失败。
- 解法：固定走 `stable-x86_64-pc-windows-gnu` 路线，不要试图修 MSVC。

### 坑 3：windows-gnu 默认链接产出"Windows 拒绝加载"的 PE
- 现象：编译"成功"，但运行报"指定的可执行文件不是此操作系统平台的有效应用程序"；Git Bash 下则报 `Exec format error`。`file` 看 PE 头完全正常。
- 根因：本机可用的 mingw binutils 是 2015 年的 ld 2.25.1，与新版 rust 的导入库/目标文件混链，产出结构损坏的 PE（链接时就有 `corrupt .drectve` 警告）。
- 解法（已固化）：仓库根 `.cargo/config.toml` 强制走 rust 自带 rust-lld：
  ```toml
  [build]
  rustflags = ["-Zunstable-options", "-Clinker-flavor=gnu-lld", "-Clinker=rust-lld", "-Clink-self-contained=y"]
  [env]
  RUSTC_BOOTSTRAP = "1"   # stable 上用 -Z 需要
  ```
  验证命令：`RUSTC_BOOTSTRAP=1 rustc -Zunstable-options -C linker-flavor=gnu-lld -C linker=rust-lld -C link-self-contained=y main.rs`

### 坑 4：rustup 自带的 self-contained dlltool.exe 不能用
- 现象：`CreateProcess` 失败——它内部调 `as.exe`，但 self-contained 目录里没有。
- 解法：用 `tools/m2w64`（anaconda 的 m2w64-binutils）里的 binutils，把它排在 PATH 前面；不要用 rustup 那份。

### 坑 5：ld 找不到导入库时，LIBRARY_PATH 不顶用
- 现象：`-lmsvcrt -luser32 -lkernel32` 等找不到；设了 `LIBRARY_PATH` 也没用（链接实际经 gcc 驱动转发，行为不符合预期）。
- 解法：不要折腾环境变量，直接按坑 3 切 rust-lld 根治。

### 坑 6：Git Bash 的 `/usr/bin/link.exe` 会遮蔽 MSVC 的 link
- 解法：GNU 路线下与此无关；若未来修 MSVC，先处理 PATH 遮蔽。

## 2. 资源编译（windres）

### 坑 7：windres 预处理要调 gcc，缺了报 "preprocessing failed"
- 现象：build 脚本报 `windres failed to compile resource.rc (exit code: 1)`，手动跑 windres 看到 `'gcc' 不是内部或外部命令`。
- 根因：windres 用 `gcc -E` 做预处理；PATH 里只加了 binutils 目录、没加 gcc 目录。
- 解法：PATH 必须**同时**包含 `tools/m2w64/Library/mingw-w64/bin`（binutils，含 windres）和 `tools/m2w64-gcc/Library/mingw-w64/bin`（gcc）。`scripts/dev-shell.sh` 已配好。

## 3. 进程与窗口操作（Git Bash 环境）

### 坑 8：Git Bash 无法直接执行本工程编译的 exe
- 现象：`./chaojiandai.exe` 报 `Exec format error`，但 `file` 显示是合法 PE。
- 解法：用 `powershell -NoProfile -Command "Start-Process '...'"` 或 `cmd /c` 启动；不要用 `cmd //c start`（见坑 9）。

### 坑 8b：GDI 截屏（CopyFromScreen）会漏拍分层透明窗口，排查时极易误判为"窗口没渲染"
- 现象：桌宠在屏幕上明明可见，GDI 全屏截图里整个窗口消失；曾因此误判为 WebGL 合成失败，白查半天。
- 解法：截屏一律用 DXGI 方式——`scripts/screenshot_dxgi.py`（python + dxcam，截的是物理分辨率 2560x1600，比 GDI 的逻辑分辨率还清晰）。注意 GDI 截屏在开启远程控制/投屏类会话后更容易漏拍。

### 坑 8c：exe 运行中无法覆盖编译，报"拒绝访问 (os error 5)"
- 解法：每次 `cargo build` 前先 `powershell Stop-Process -Name chaojiandai -Force`。已列入标准构建流程。

### 坑 8d：PowerShell 5.1 按 GBK 读脚本，含中文注释的 .ps1 会直接解析失败
- 现象：`MissingEndCurlyBrace` 之类莫名报错。
- 解法：`scripts/*.ps1` 里只写 ASCII（注释也用英文）。

### 坑 9：`cmd //c start` 和 `tasklist //FI` 在 Git Bash 里会挂起
- 现象：命令不返回直到超时。
- 解法：一律改用 PowerShell——启动用 `Start-Process`，查进程用 `Get-Process`。

### 坑 10：cargo 有时不显示 build 脚本（build.rs）的 stderr
- 现象：`failed to run custom build command (exit code: 101)`，只有 stdout，panic 信息看不到；还会重放旧的缓存输出，极具迷惑性。
- 解法（定位法）：在 build.rs 里 `std::panic::catch_unwind(|| tauri_build::build())`，把 panic 信息写进文件再退出：
  ```rust
  let p = std::path::Path::new(&std::env::var("OUT_DIR").unwrap())
      .parent().unwrap().parent().unwrap().join("build-panic.txt");
  ```
  配合 `cargo clean -p <包名>`（别 clean 全部，重编译很慢）强制重跑。
- 补充：前端状态排查可让页面把状态 `invoke` 给 Rust 写日志文件（`debug_log` command，日志在 `%TEMP%\chaojiandai-debug.log`），比截图可靠。

### 坑 10b：排查"窗口内容不显示"类问题时，先怀疑截图工具，再怀疑渲染
- 教训：曾同时改两个变量（noRedirectionBitmap + disable-gpu-compositing）导致无法归因；且这两个标志在本机均为死路（WebGL 内容不进合成、FPS 掉到 23），**不要再用**。

## 4. Tauri 配置

### 坑 11：`core:window:allow-is-ignore-cursor-events` 权限在 Tauri 2 不存在
- 现象：tauri-build 直接报错（编译期），不是运行期警告。
- 解法：capabilities 里删掉它；需要"读"穿透状态就用 JS 侧自己维护状态（`src/main.ts` 已是这么做的）。

## 5. 网络与下载

### 坑 12：GitHub 直连不通
- 解法：下载走清华镜像 `mirrors.tuna.tsinghua.edu.cn`；npm/rustup 源已配好可用。mingw 工具链来源（anaconda 的 msys2 频道）：
  - `m2w64-binutils-2.25.1-5.tar.bz2` → `tools/m2w64`（windres/as/ld/dlltool）
  - `m2w64-gcc-5.3.0-6.tar.bz2` → `tools/m2w64-gcc`（gcc，windres 预处理用）

## 6. 目录约定

- `tools/m2w64*`：mingw 工具链（已 gitignore，241MB 不进仓库）。**不要放回 /tmp**——重启即丢，曾因此折腾过。
- `scripts/dev-shell.sh`：唯一环境入口，新 shell 先 source 它。
- `scripts/check-window.ps1`：窗口扩展样式验证（LAYERED/TRANSPARENT/TOPMOST 等）。
- `src-tauri/target/`：编译缓存，**禁止 cargo clean**（全量重编译 3 分钟以上）；只许 `cargo clean -p chaojiandai`。
