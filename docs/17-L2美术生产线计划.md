# L2 美术生产线计划：美术子 agent + 插件化生产（草稿 · 待讨论定稿）

> 状态：**草稿**。定位：#16 方案 D3 的落地路线。架构变更（2026-11-25 用户拍板方向）：
> **不注册任何外部 3D 平台**，美术生产全部由专职子 agent 用本环境已装插件完成。
> 经核实：model3d_generation 插件底层 = Tripo API（随 Kimi Work 内置），文/图/多视图生成、
> 低模、四边面、指定面数、裸几何全支持；绑定与动画插件不做，由 Blender 承担（届时安装）。

## 1. 目标

一条可复用的资产生产线，覆盖四类资产（主角生物 / 场景套件 / 物件道具 / 英雄精修）。
第一单 meili 水獭原型。每一步幂等可重跑，产物可追溯。

## 2. 总架构

```
美术子 agent（专职，Agent 工具派发）
  │
  ├─ 概念稿   image_generation 插件      → art/concept/<name>.*.png
  ├─ 生成     model3d_generation 插件    → art/raw/<name>.glb   （Tripo 底层）
  │           （文生/图生/多视图、低模 p2、--no-texture、decimate）
  ├─ 绑骨动画 Blender（届时装，~300MB 镜像）→ 补骨骼 + clip + 手做招牌动作
  ├─ 标准化   gltf-transform（npm）       → public/models/<name>.glb
  └─ 入库     species 配置 + 实机验收 + 编辑器插件预览检查
```

- **子 agent 的职责边界**：只负责美术资产的生产与自检（出图、出模、查预览图）；
  入库接线（species 配置、前端加载）仍由主 agent 在工程会话里做，保持代码责任单一；
- 每段产物是文件，幂等可重跑；生成失败重试/换参数由子 agent 按 SKILL.md 的规程处理。

## 3. 各段设计

### 段1：概念稿

- `species/<name>.concept.md`（性格要点 + 必保留特征，人写）→ image_generation 出定稿图，
  需要多视图时追加同角色侧/背视图（Tripo 多视图生成吃 2-4 张同姿态图）
- 风格锁定：prompt 模板固化（软低多边形、圆润充气感、粘土质感、无复杂纹理、
  深海水族馆×罗小黑风格），存 `scripts/art-pipeline/style_prompt.txt`
- **全链唯一强制人工点**：人看图拍板后才进段2

### 段2：生成（model3d_generation 插件）

- 首选 `--model p2`（48–50,000 面，可 `--quad` 四边面，利于后续绑骨变形）+
  `--face-limit`（主角 ≤1.5 万）+ `--no-texture`（裸几何，风格由渲染端定）
- 不满意时插件内继续 `decimate` / `segment`+`complete` 修结构，不从头重生成
- 产出 `art/raw/<name>.glb`（不进 public）
- 成本：随 Kimi Work 订阅走 agent-gw，**无单独注册、无按次付费**；生成排队/耗时按插件规程（提交一次+看守）

### 段3：绑骨 + 动画（Blender，首次执行前安装）

- 自动绑骨路线待实测择优（Blender 插件生态 / Mixamo 免费网页上传 / Rigify 手绑三选一，
  在 meili 原型上试，选 deform 质量最好的）；四边面网格 + ≤1.5 万面是绑骨的友好输入
- 动作来源：**Quaternius CC0 动作库重定向**（免费可商用、风格同为低模卡通，
  与我们的美术基调天然契合）+ 平台动作库导出的 clip 备选
- **招牌动作**（搓脸/递贝壳等物种专属）手做关键帧——这是 AI 换不掉的部分
- clip 命名按 §16 约定（`idle_a/jump/wave/listen…`）
- 产出：补完骨骼动画的 GLB

### 段4：标准化 + 入库

- gltf-transform：减面复核 / 剥纹理 / 统一朝向比例 / clip 重排 → `public/models/<name>.glb`
- `species/<name>.toml` 配置；实机验收（唤醒/摸头/拖拽/巡逻/倾听反馈逐项）
- CC0 素材（动作/底模）授权凭证归档 `docs/licenses/`

## 4. 目录

```
scripts/art-pipeline/
  style_prompt.txt   # 风格 prompt 模板（单一事实来源）
  README.md          # 子 agent 的操作规程（步骤、验收标准、常见坑）
art/concept/  art/raw/   # 中间产物（大二进制不进 git，留小样）
public/models/         # 终产物（进 git）
species/               # 物种配置（进 git）
docs/licenses/         # 授权凭证（进 git）
```

## 5. 成本

| 项 | 花费 |
|---|---|
| 概念图 + 网格生成 | 随 Kimi Work 订阅（agent-gw），$0 边际 |
| Blender | $0（开源），仅安装成本 |
| CC0 动作/底模 | $0 |
| 升级触发线：插件生成质量长期不达标 | 才评估 Meshy/Tripo 官方付费档（$20/月） |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 插件生成质量参差（Tripo 与 Meshy/Rodin 存在口碑差距） | p2 四边面 + 多视图喂图提高下限；不达标重生成；最终兜底 = 英雄资产走 CC0 底模改造或付费档 |
| 插件不做绑骨动画，Blender 环节成为瓶颈 | 提前在 meili 原型实测三条绑骨路线；最坏情况动作先全走程序动画（LookAt/ procedual）顶着 |
| Blender Windows 版安装踩坑 | 走清华镜像 + 锁版本；装不上则绑骨阶段暂停，产品侧先用无骨骼版（整只模型做程序动画）降级运行 |
| 子 agent 产出无人验收（workslop） | 每段有明确自检（预览图/多视角渲染），入库必须过实机；风格漂移时回到 style_prompt.txt 单一来源 |

## 7. 里程碑

| 步骤 | 内容 | 验收 | 依赖 |
|---|---|---|---|
