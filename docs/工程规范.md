# 《潮间带》工程规范

> 状态：v1.0（2026-11-11，随 M1 启动生效）
> 适用范围：`src-tauri/`（Rust）、`src/`（TypeScript）、`pets/`（内容包）、`scripts/`（工具）
> 定位：本项目的代码"写法宪法"。**本项目的特殊性：大量代码由 AI 生成——规范的第一受众是 AI，第二受众才是人。** 模块边界、类型严格度就是 AI 的护栏，宁严勿宽。

---

## 0. 总则

1. **简单优先**：单人项目 + AI 协作，可读性 > 精巧。禁止"为了扩展性"引入抽象；先写直的，出现第二处重复才抽象。
2. **接口先行**：跨模块的协议/类型先定稿再实现（IPC 事件 JSON、DB schema、内容包 manifest 是三个典型）。类型即文档。
3. **每条红线有代码门禁**：性能预算（架构 §7）与隐私红线（架构 §3.1 末、§6）不靠自觉，靠评审清单和 CI。

---

## 1. 仓库结构细则

### Rust 侧（`src-tauri/src/`）——按"能力域"分模块，不按"技术角色"

```
src-tauri/src/
├── main.rs              # 只放装配（plugin 注册、路由注册、启动顺序），不放逻辑
├── ipc.rs               # 全部 IPC 命令的定义与参数类型（specta 导出源）
├── event_bus.rs         # 事件总线：标准化事件的唯一集散地
├── event_collector/     # 采集器：每个事件源一个文件
│   ├── mod.rs           #   Collector trait + 注册表
│   ├── foreground.rs    #   GetForegroundWindow
│   ├── smtc.rs          #   SMTC 音乐
│   ├── power.rs         #   电源/电池
│   ├── mouse.rs         #   WH_MOUSE_LL
│   ├── window_track.rs  #   SetWinEventHook 位置跟踪
│   └── beat.rs          #   WASAPI loopback 节拍（仅音乐播放时开启）
├── debounce.rs          # 防抖器（阈值+滞回+冷却），采集器与行为引擎共用
├── voice/               # 语音管线
│   ├── mod.rs           #   状态机（M0-3 的 IDLE/LISTENING 状态机产品化）
│   ├── kws.rs  vad.rs  asr.rs  tts.rs  # 每个组件一个文件，接口 trait 化
│   └── intent.rs        #   意图路由（本地规则/本地 LLM/云端）
├── perception/          # 截屏感知（触发器/脱敏/分析/写入/透明 五段各一个函数）
├── llm/                 # sidecar 进程管理 + prompt 装配
│   ├── sidecar.rs       #   进程生命周期（守护/健康检查/休眠）
│   └── persona.rs       #   人设模板与注入
├── cloud/               # BYOK 云通道（OpenAI 兼容抽象）
├── db/                  # schema、迁移、写穿策略
│   ├── schema.sql       #   唯一 schema 来源
│   └── repo.rs          #   每张表一组类型安全查询函数，SQL 只许出现在这里
├── hooks/               # 全局钩子注册与卸载
└── settings.rs          # 设置读写（隐私档、配置项）
```

**Rust 模块规则**：
- `mod.rs` 只做 re-export 和 trait 定义，实现放同名子文件；
- 跨模块调用**只走 pub trait**，不 pub 具体类型——这是 AI 生成代码不越界的主要手段；
- `main.rs` 超过 100 行即视为装配过载，拆出去。

### TypeScript 侧（`src/`）——分层 + 按功能域

```
src/
├── main.ts              # 入口：装配 only
├── ipc/                 # 与 Rust 通信的唯一入口（生成的类型 + 封装函数）
│   ├── types.ts         #   specta 生成的绑定（不手改，CI 校验新鲜度）
│   └── client.ts        #   invoke/订阅的封装，业务代码只 import 这里
├── behavior/            # 行为引擎（存在感光谱/四道闸/映射执行器/一日节奏）
├── presentation/        # 表现层（Three.js 场景/动画状态机/视线/口型）
├── game/                # 游戏系统（数值曲线/照顾/告别/书信/图鉴）
├── pets-runtime/        # 内容包加载/校验/热更新（petpack v1 schema 在这里）
├── ui/                  # DOM 覆盖层（气泡/信件/设置/事件监视器调试页）
└── assets/              # 静态资源
```

**TS 规则**：
- 业务代码**禁止直接 `invoke`**，必须经 `ipc/client.ts`——换协议时只改一处；
- 表现层与行为层之间用事件通信，不互相 import 内部实现；
- `presentation/` 里禁止出现游戏数值逻辑（数值是 `game/` 的事）。

### 内容包（`pets/<id>/`）

- 纯数据（TOML/Markdown），**无代码**（架构 §9 风险表：防 Workshop 恶意脚本）；
- schema 校验在 `pets-runtime/`，加载失败给出人类可读错误并拒绝启动该包。

## 2. 语言规范

### Rust

- `cargo clippy -- -D warnings` 零警告准入；`cargo fmt` 提交前必跑；
- 错误处理分层：**库代码用 thiserror 定义具体错误，应用边界（IPC handler）用 anyhow 收口**；禁止在库函数里 `unwrap/expect`，允许在 `main.rs` 装配层 `expect("带原因")`；
- 日志用 `tracing`，分级纪律：`info` = 生命周期事件（启动/加载/退出），`warn` = 降级与重试，`debug` = 常规事件流，事件总线上的每个事件至少有一条 `debug`；
- **禁止静默失败**：所有 `Result` 必须处理，确实无所谓的用 `let _ =` 并注释原因。

### TypeScript

- `strict: true` 全开，禁止 `any`（不得已用 `unknown` + 收窄）；
- ESLint + Prettier 提交前必跑；禁用 `console.log` 进主分支（用统一的 `log` 模块，可整体开关——产品发布时关闭调试输出）；
- 所有跨层数据结构用 `type`/`interface` 显式声明，IPC 类型一律从 Rust 生成，**手写的 IPC 类型视为 bug**；
- 动画/渲染循环里禁止分配大对象（复用 Vector3/Quaternion，Three.js 对象池化）。

## 3. IPC 类型同步（防两端漂移的关键工程）

- Rust 侧用 [specta](https://docs.rs/specta) + `tauri-specta` 标注 IPC 类型，构建时生成 `src/ipc/types.ts`；
- CI 校验：生成的 types.ts 与 Rust 源码不一致即失败（防止"改了 Rust 忘了重新生成"）；
- 事件 JSON 骨架（`{id, ts, source, kind, payload, privacy_tier}`）的 `kind` 用枚举，新增事件类型必须同时改 Rust 枚举 + 映射表 + 文档。

## 4. 测试策略（务实版）

| 层 | 工具 | 范围 |
|---|---|---|
| Rust 单元 | `cargo test` | 纯逻辑：防抖器、数值曲线、意图路由规则、脱敏黑名单、schema 校验 |
| TS 单元 | `vitest` | 纯逻辑：四道闸、映射执行器、内容包解析 |
| IPC 契约 | CI 生成校验 | 类型漂移即红 |
| 组件探针 | `scripts/`（M0 遗产） | 语音链路、窗口移动、节拍检测等有真实硬件依赖的，保留 Python 探针做回归基线，不进 CI |
| 手工验收 | M1 计划各阶段交付项 | 桌面端体验类不自动化 |

**原则**：测纯逻辑，不测胶水；硬件/系统交互靠探针 + 手工验收清单。

## 5. AI 协作规范（本项目特色）

1. **任务 = 一个 commit**：粒度以 M1 计划的阶段内子任务为准，commit message 写清任务编号与结论（既有规矩延续）；
2. **开工先读**：`docs/踩坑与环境档案.md`（环境）、本规范（写法）、上游计划（做什么）；新坑随手入库（既有规矩延续）；
3. **AI 生成代码的入库门槛**：类型齐全、无 clippy/ESLint 告警、关键路径有日志；**超过 300 行的单文件必须人工触发拆分期——AI 倾向于写大文件，发现即拆**；
4. **接口文件（`ipc.rs`、schema、petpack manifest）改动必须人审**：协议改动影响全局，AI 不得顺手改；
5. AGENTS.md 置顶三条规矩（commit 粒度、踩坑档案、右下角调试）继续有效，本规范作为第四条补充进 AGENTS.md。

## 6. CI 检查项（M1-1 搭好，此后每次提交跑）

- `cargo fmt --check` + `cargo clippy -- -D warnings` + `cargo test`
- `eslint` + `tsc --noEmit` + `vitest run`
- IPC 生成物新鲜度校验
- `cargo-deny` + `npm license-checker`（白名单 MIT/Apache 及变体；GPL/AGPL/CC-BY-NC 出现即拦——架构 §9.1 检查点 3 的自动化）
- 构建产物冒烟：安装包能装能启动（ nightly 跑一次即可，不必每次提交）

---

## 7. 两条红线的评审清单（每次涉及相关代码的改动自查）

**性能**（架构 §7）：新增常驻线程？→ 说明必要性。新增轮询？→ 频率 ≤1Hz 或有事件驱动替代。新增内存常驻？→ 对账 300MB 预算。

**隐私**（架构 §6）：新增出机数据？→ 过隐私档闸门了吗、隐私日志写了吗。新增采集项？→ 对照 §3.1 红线（剪贴板/键盘记录永不碰）。新增依赖？→  license-checker 白名单过没过。
