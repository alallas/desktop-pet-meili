# L2 美术生产线计划：API/CLI 化 + 通用 agent 编排（草稿 · 待讨论定稿）

> 状态：**草稿**。标 🔲 的决策点需用户拍板。定位：这是 #16 方案 D3 的落地路线——
> 不把流水线交给平台（L1 订阅制），而是把流水线**写成仓库里的脚本链**，由 agent
> （Kimi Work）在会话中编排执行。产物直接落仓库，验收走现有实机测试。

## 1. 目标

一条可复用的资产生产线，覆盖四类资产（主角生物 / 场景套件 / 物件道具 / 英雄精修），
每一步都可单独重跑、可 mock 不烧钱、产物可追溯授权。第一单是 meili 水獭原型（M-b）。

## 2. 总架构

```
概念稿 ──→ 生成 ──→ 标准化 ──→ 入库验收
(段1)     (段2)     (段3)       (段4)
image_    Meshy     Blender     species 配置 +
generation API      headless    实机测试平台
prompt    图生3D    python      + 人工验收
模板      +绑骨+动作 批处理
```

- **编排者 = agent**：每一段是一个可独立运行的脚本，agent 负责按序调用、看输出、
  失败后重试/降级（如 Meshy 失败切 Tripo）。不引入 workflow 平台；
- **幂等可重跑**：每段的输入输出都是文件，跑过的段跳过（产物在就不重花钱）；
- **mock 模式**：段2 支持 `--mock`（用现成 GLB 替身走完后两段），开发调试不消耗 API 额度。

## 3. 各段设计

### 段1：概念稿（`scripts/art-pipeline/concept.py`）

- 输入：`species/<name>.concept.md`（性格要点 + 必保留特征清单，人写）
- 生成：image_generation 插件出 1 张定稿概念图；需要多视图时追加"同一角色侧面/背面"提示词出 2-3 张
- 风格锁定：**prompt 模板固化在脚本里**，物种名可变、风格后缀固定：
  `软低多边形、圆润充气感、粘土质感、无复杂纹理、深海水族馆×罗小黑风格、干净柔和配色`
- 产出：`art/concept/<name>.front.png`（+ `.side.png` `.back.png`）
- 验收：人看图拍板，这是全链唯一强制人工点（段1 不过，后面全是白费）

### 段2：生成（`scripts/art-pipeline/gen_mesh.py`）

- 首选 **Meshy API**（角色管线最全：图生 3D → 拓扑 → 绑骨（人形+四足，2026-11-18 上线）→ 动作库 → 导出 GLB 含动画 clip）
- 流程：`image-to-3d` → `remesh`（面数控制）→ `rig`（骨架模板选 humanoid）→ 动作库挑清单
  （每物种一份 `actions.toml`：idle×2-3 / walk / jump / wave / sit / sleep / petted / held / listen…）→ `export GLB`
- 备选 **Tripo API**（Meshy 失败或质量不达标时切换，脚本抽象一层 `provider` 接口，两家的适配器各一个文件）
- 产出：`art/raw/<name>.glb`（未标准化，不进 public）
- 费用：按次计费（约 $0.10–0.30/次操作），单物种全流程预计 $2–5；凭据读环境变量
  `MESHY_API_KEY`（本地 `.env`，**不进 git**，README 写明获取方式）

### 段3：标准化（`scripts/art-pipeline/standardize.py`，Blender headless）

Blender 以 `--background --python` 无头跑，步骤全部脚本化：

1. **减面**到预算（按类别查表：主角 ≤1.5 万三角 / 场景件 ≤2 万 / 物件 ≤2k）
2. **剥纹理**：删全部贴图材质，换纯色/顶点色材质（渲染风格由 three.js 卡通着色决定，已定稿）
3. **统一**：朝向（正面 -Z→+Z 按现有管线约定）、落地高度、比例（以 meili 身高为基准 1 单位）
4. **clip 重命名**：按 §16 方案 clip 命名约定（`idle_a/jump/wave/listen…`），Mixamo/平台原名进映射表
5. 导出 GLB 到 `public/models/<name>.glb`

产出直接进前端加载目录。Blender 本体是前置依赖（不入 git，走清华镜像装，见踩坑档案坑 26 类）。

### 段4：入库验收

1. `species/<name>.toml` 写配置（模型路径、口癖、倾听参数、动作映射）
2. 启动应用走实机：唤醒/摸头/拖拽/巡逻/倾听反馈逐项过
3. 授权凭证归档 `docs/licenses/<provider>-<date>.pdf`（Steam 发行审计用，产品设计 §10.1）

## 4. 目录与文件

```
scripts/art-pipeline/
  concept.py        # 段1：概念图生成（image_generation 插件包装）
  gen_mesh.py       # 段2：Meshy/Tripo API 编排（--mock / --provider tripa）
  standardize.py    # 段3：Blender 无头标准化
  actions.toml      # 每物种动作清单（按物种分节）
  style_prompt.txt  # 风格后缀模板（单一事实来源）
art/                # 中间产物（.gitignore 大二进制，只留小样）
  concept/  raw/
public/models/      # 终产物（进 git）
species/            # 物种配置（进 git）
docs/licenses/      # 授权凭证（进 git）
```

## 5. 费用与升级触发线

| 阶段 | 花费 |
|---|---|
| 脚本链开发 + mock 调试 | $0 |
| meili 原型一单 | $2–5（API 按次） |
| 触发线：单月起量 >3 只生物 或 需要批量复用流程 | 升级 Meshy Pro $20/月，或评估 Tripo Agentic Canvas（L1） |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| image→3D 质量参差（学术实证的质量瓶颈） | 概念图出多视图喂入；不达标重生成（按次计费可承受）；英雄资产兜底 = Quaternius CC0 底模改造（零元档方案） |
| Meshy 绑骨骨架非 Mixamo，动作库 clip 与现有管线假设冲突 | 段3 统一重命名 + 段4 实机验收兜底；真冲突再评估 Mixamo 重定向 |
| API 条款/价格变动 | provider 抽象层；凭证与条款截图归档，定期复查 |
| Blender 脚本环境在本机不稳 | mock 数据先打通段3；Blender 装不上则降级为 three.js 端运行时减面（`SimplifyModifier` 等价物） |
| 招牌动作（搓脸/递贝壳）AI 做不出 | 段2 动作清单标注 `handmade: true`，段3 跳过这些 clip，Blender 手做补录（记入物种 backlog） |

## 7. 里程碑

| 步骤 | 内容 | 验收 | 花钱 |
|---|---|---|---|
| P1 | 目录骨架 + provider 抽象 + 段1 概念 prompt 模板固化，段2 mock 模式 | 替身 GLB 走完段3-4，meili 配置加载成功 | $0 |
